App Store / builds — sans compte Apple vs avec compte payant
===========================================================

Phase A — sans Apple Developer Program (maintenant)
----------------------------------------------------
  • Développement local : npm start, expo run:ios sur simulateur si tu as Xcode (macOS).
  • Android : eas build --platform android (pas besoin du programme Apple).
  • iOS simulateur cloud : npm run eas:build:ios:sim (profil ios_simulator dans eas.json).
    → Installe le .tar.gz sur simulateur macOS ; pas d’App Store ni TestFlight sans compte payant.
  • expo-doctor : npm run doctor — corriger tant que possible avant tout build cloud.

Phase B — compte Apple Developer actif (99 $/an)
-------------------------------------------------
Identifiants déjà configurés dans app.json :
  • iOS bundleIdentifier : com.appigeek.reader
  • Android package       : com.appigeek.reader  (pour une release Play plus tard)
  • buildNumber iOS initial : 1  (EAS production incrémente automatiquement)
  • Chiffrement : usesNonExemptEncryption = false (HTTPS classique uniquement)

1) Compte Expo (gratuit) + lien du projet
   npm run eas:login
   npm run eas:init
   → crée le projet EAS et peut ajouter "extra.eas.projectId" dans app.json
   OK sur ce dépôt : projectId + owner dorian172 ; slug Expo = "appy-geek" (doit
   correspondre au projet EAS @dorian172/appy-geek, pas "appigeek").

2) Apple : dans developer.apple.com — enregistrer un App ID identique à bundleIdentifier
   com.appigeek.reader (si pas déjà créé par EAS).

3) App Store Connect — créer l’app (nom, langue, bundle id).

4) Build production iOS (sur les serveurs Expo, certificats gérés par EAS au premier build)
   npm run eas:build:ios
   Premier build : lancer en mode INTERACTIF (pas --non-interactive) pour qu’EAS
   crée / valide les certificats Apple (Distribution) avec ton compte développeur.

5) Soumission TestFlight / App Store
   npm run eas:submit:ios
   (Apple ID, mot de passe app-specific si A2F, équipe… demandés à l’exécution)

A prévoir côté App Store Connect (pas dans ce dépôt) :
  • Captures d’écran iPhone (tailles imposées par Apple)
  • Texte description, mots-clés, catégorie
  • URL politique de confidentialité (souvent obligatoire)
  • Questionnaire confidentialité / tracking

Variante : build local Xcode nécessite macOS + CocoaPods — le flux EAS cloud évite ça.
